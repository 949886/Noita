# Threaded Chunk Streaming Guide

This version moves the expensive world-streaming work out of the frame that the player is moving in.

## What now runs in the background

Normal piece chunks are generated by `ChunkGenerationWorker`:

- biome / chunk type lookup
- canonical socket profile lookup through `WorldSeamRegistry`
- piece selection
- glue generation
- seam repair analysis
- visual `Image` composition
- material `Image` composition

Special chunk images are generated by `SpecialChunkImageWorker` through `SpecialPieceImageBuilder`:

- special room image fill
- noise pass
- carved room pass
- socket-profile entrances
- decorative image details

## What still runs on the main thread

The following must stay on the main thread because they touch the scene tree or rendering server:

- creating `PieceChunkRenderer` nodes
- creating `SpecialPieceRenderer` nodes
- calling `ImageTexture.create_from_image()`
- assigning textures to `Sprite2D`
- adding/removing children
- updating the HUD and world debug overlay

This is why the system is split into two stages:

```text
background thread:
  PieceChunkData + Image

main thread:
  ImageTexture + Node/Sprite setup
```

## Piece image cache

`PieceLibrary.prepare()` now calls `PieceDef.prepare_image_cache()` on every piece.

That converts each piece texture into prepared `Image` data on the main thread before workers start. This avoids doing the following inside the worker loop:

```text
Texture2D.get_image()
decompress()
convert()
resize()
```

The worker only reads the cached `Image` and blits it into the chunk image.

## Runtime options on WorldManager

```text
use_threaded_chunk_generation
```

Enables the normal chunk worker. Recommended: `true`.

```text
use_threaded_special_generation
```

Enables the special image worker. Recommended: `true`.

```text
main_thread_upload_budget_per_frame
```

Limits how many ready results may be converted into renderers/textures in one frame. Recommended desktop starting value: `2`. Mobile performance mode caps this to `1`.

Lower values reduce spikes but make chunks appear later. Higher values fill the world faster but can reintroduce upload stutter.

```text
debug_update_interval
```

Controls how often the F1 HUD recomputes and redraws debug text. Recommended: `0.20` seconds.

## Why stutter should be reduced

Before this refactor, crossing a chunk boundary could synchronously generate a full new strip of chunks in one frame.

Now crossing a boundary does this instead:

```text
player moves
  ↓
WorldManager computes needed chunks
  ↓
missing chunks are queued
  ↓
background worker builds chunk Images
  ↓
main thread uploads at most N textures per frame
```

So the expensive CPU work is no longer packed into the same frame as player movement.

## Mobile performance pass

`MOBILE_PERFORMANCE_GUIDE.md` documents the extra mobile-oriented pass layered on top of this threaded architecture. In short:

- normal and special chunks share one total texture-upload budget per frame;
- mobile mode caps that budget to `1`;
- debug overlays start hidden;
- chunk/special renderers are pooled;
- CPU `visual_image` data is released after upload by default;
- mobile mode uploads half-resolution visual textures (`512 -> 256`) and scales sprites with nearest filtering.

## Remaining possible stutter source

`ImageTexture.create_from_image()` still happens on the main thread. The upload budget and visual downscale reduce the spike, but texture upload cannot be fully moved into the current worker.

For future optimization, consider:

- active/preload radius separation
- glue image caching
- dynamic worker throttling
- splitting very large special chunks into smaller textures

## Debug HUD fields

The F1 HUD now includes streaming stats:

```text
Pending
```

Normal chunks requested but not yet attached.

```text
Async chunks on/off
```

Whether the normal chunk worker is active.

```text
q/r
```

Worker queue count / worker result count.

```text
special q
```

Special chunks waiting for image generation or upload.

```text
last gen/upload
```

Last normal chunk background generation time in milliseconds / how many generated chunks were uploaded this frame.



## Runtime profile integration

Threading and streaming knobs are now loaded from `WorldRuntimeProfile` resources instead of being hard-coded as mobile-only overrides on `WorldManager`.

- PC profile: full-resolution visuals, larger load radius, larger upload budget.
- Mobile profile: smaller load radius, one shared texture upload per frame, visual downscale, CPU visual-image release after upload.

The worker model is unchanged: background threads build `Image` data, and the main thread still creates `ImageTexture` objects and scene nodes.
